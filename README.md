# Image Hosting Server

## Описание проекта

Image Hosting Server — это веб-приложение для загрузки, хранения и просмотра изображений.

Приложение содержит страницы Home, About и Products. На странице Home расположена форма для ввода имени и фамилии пользователя. Введённые данные сохраняются в файле users.json.
**Важно:** данная форма предназначена только для сохранения данных пользователя и не является полноценной системой регистрации и авторизации. Страница Products и функция загрузки изображений доступны без регистрации.

Пользователь может загрузить изображение через веб-форму, после чего сервер:
- проверяет формат и размер файла;
- генерирует уникальное имя;
- сохраняет изображение;
- возвращает прямую ссылку на загруженный файл.

Изображения раздаются через Nginx.

## Возможности

- навигация между страницами Home, About и Products;
- ввод имени и фамилии пользователя через веб-форму;
- хранение данных пользователей в `users.json`;
- загрузка изображений через веб-интерфейс;
- поддержка форматов `.jpg`, `.png`, `.gif`;
- максимальный размер файла — 5 МБ;
- генерация уникального имени файла;
- доступ к изображениям по прямой ссылке;
- логирование успешных загрузок и ошибок;
- хранение изображений и логов в Docker Volumes;
- запуск проекта с помощью Docker Compose;
- сохранение метаданных изображений в PostgreSQL;
- просмотр списка загруженных изображений с информацией о файлах;
- удаление изображений через веб-интерфейс с удалением файла и записи из базы данных;
- постраничный просмотр изображений (пагинация, по 10 записей на страницу);
- резервное копирование базы данных PostgreSQL с помощью pg_dump;
- восстановление базы данных с помощью pg_restore;
- резервное копирование загруженных изображений;
- проверка резервных копий и тестовое восстановление данных.

## Технологии

- Python 3.13
- `http.server` — HTTP-сервер Python
- Nginx — раздача изображений и проксирование запросов
- Docker — контейнеризация приложения
- Docker Compose — запуск и взаимодействие сервисов
- PostgreSQL 17 — хранение метаданных загруженных изображений
- psycopg2 — подключение Python-приложения к PostgreSQL и выполнение SQL-запросов

## Назначение основных файлов

- `app.py` — основной Python-сервер: обрабатывает HTTP-запросы, отображает страницы, принимает данные пользователей и загружает изображения, сервер также взаимодействует с PostgreSQL, формирует список изображений, обрабатывает пагинацию и удаление.
- `json_tools.py` — содержит функции для чтения данных из JSON-файла и записи данных в него.
- `users.json` — хранит данные пользователей, отправленные через форму на странице Home; файл подключается к контейнеру приложения через bind mount.
- `static/index.html` — главная страница Home с формой для ввода имени и фамилии пользователя.
- `static/about.html` — страница About с информацией о сервисе.
- `static/products.html` — страница Products с формой загрузки изображений.
- `nginx.conf` — конфигурация Nginx для проксирования запросов к приложению и раздачи изображений.
- `Dockerfile` — инструкция для сборки Docker-образа Python-приложения.
- `compose.yaml` — описывает три сервиса (`app`, `nginx`, `db`), настройку портов, переменных окружения, проверку готовности PostgreSQL и подключение Docker Volumes (`images`, `logs`, `db_data`).
- `requirements.txt` — список Python-зависимостей проекта.
- `images/` — локальный каталог проекта; при запуске через Docker изображения хранятся в Docker Volume, подключённом к `/app/images`.
- `logs/` — локальный каталог проекта; при запуске через Docker логи хранятся в Docker Volume, подключённом к `/app/logs`.
- `static/images_list.html` — HTML-шаблон страницы со списком загруженных изображений, таблицей и пагинацией.
- `static/image_row.html` — HTML-шаблон строки таблицы с информацией об изображении и кнопкой удаления.
- `backups/images_db.dump` — резервная копия базы данных PostgreSQL.
- `backups/images/` — резервные копии загруженных изображений.
- `test_pagination.py` — вспомогательный скрипт для автоматической загрузки тестовых изображений.
- `test.jpg` — изображение, используемое для тестирования.
- `.env` — файл с переменными окружения, который не должен публиковаться в репозитории.

## Требования к окружению

Для запуска проекта необходимо установить:

- Docker
- Docker Compose

Python и Nginx отдельно устанавливать не требуется, так как они запускаются внутри Docker-контейнеров.

## Запуск проекта

1. Откройте терминал в корневой папке проекта.

2. Подготовьте файлы конфигурации.

   Создайте файл `.env` на основе `.env.example`:

   ```powershell
   Copy-Item .env.example .env
   ```

   Откройте файл `.env` и замените `your_password_here` собственным паролем PostgreSQL:

   ```dotenv
   DB_PASSWORD=your_password_here
   ```

   Создайте файл `users.json` на основе `users.example.json`:

   ```powershell
   Copy-Item users.example.json users.json
   ```

   Изначально файл `users.json` содержит пустой список `[]`.
   Данные, введённые в форму на главной странице, сохраняются в этот файл.

   **Важно:** файлы `.env` и `users.json` не публикуются на GitHub,
   поскольку могут содержать конфиденциальные данные.

   Команды `Copy-Item` предназначены для PowerShell в Windows.

3. Соберите образы и запустите контейнеры:

   ```bash
   docker compose up -d --build
   ```

После запуска приложение доступно по адресам:

- `http://localhost:8000` — прямой доступ к Python-бэкенду;
- `http://localhost:8080` — доступ к приложению через Nginx.

Основной адрес для работы с приложением:

`http://localhost:8080`

## Маршруты и функциональность

- `GET /` — главная страница Home с формой для ввода имени и фамилии пользователя.
- `GET /about` — страница About с информацией о сервисе.
- `GET /products` — страница Products с формой для загрузки изображения.
- `POST /users` — принимает данные из формы Home и сохраняет пользователя в `users.json`.
- `POST /upload` — принимает изображение, проверяет формат и размер, сохраняет файл с уникальным именем.
- `GET /images-list?page=N` — отображает список загруженных изображений с пагинацией (10 записей на страницу).
- `POST /delete/<id>` — удаляет изображение и соответствующую запись из PostgreSQL.
- `GET /images/<filename>` — возвращает загруженное изображение через Nginx.

## Логирование

Успешные загрузки и ошибки записываются в файл:

```text
logs/app.log
```

При запуске через Docker каталог логов подключается как Docker Volume, поэтому логи сохраняются между перезапусками контейнеров.

Пример записи:

```text
[2026-09-06 17:16:15,089] UPLOAD: image 2305150f8fa7431c98d76b3a61206bb3.jpg saved successfully
```

## Резервное копирование и восстановление PostgreSQL

Для резервного копирования базы данных используется утилита pg_dump, а для восстановления — pg_restore.

### Создание резервной копии
Создайте резервную копию базы данных внутри контейнера PostgreSQL:

```bash
docker compose exec -T db pg_dump -U postgres -d images_db -Fc -f /tmp/images_db.dump 
```

Скопируйте архив из контейнера в папку проекта:

```bash
docker compose cp db:/tmp/images_db.dump ./backups/images_db.dump
```

### Восстановление базы данных

Для безопасной проверки восстановления можно создать отдельную тестовую базу:

```bash
docker compose exec db createdb -U postgres images_db_test
```

Скопируйте резервную копию в контейнер:

```bash
docker compose cp ./backups/images_db.dump db:/tmp/images_db_check.dump
```

Восстановите данные в тестовую базу:

```bash
docker compose exec db pg_restore -U postgres -d images_db_test /tmp/images_db_check.dump
```

Проверьте количество восстановленных записей:

```bash
docker compose exec db psql -U postgres -d images_db_test -c "SELECT COUNT(*) FROM images;"
```

**Важно:** pg_dump сохраняет структуру и данные PostgreSQL, но не сами файлы изображений. Их необходимо копировать отдельно.


## Резервное копирование изображений

Загруженные изображения хранятся в Docker Volume `images`.

### Создание резервной копии

Скопируйте изображения из контейнера приложения в папку `backups`:

```bash
docker compose cp app:/app/images ./backups/
```

### Восстановление изображений

Для восстановления файлов из резервной копии используйте:

```bash
docker compose cp ./backups/images/. app:/app/images/
```

**Важно:** восстановление может перезаписать существующие файлы с одинаковыми именами. Перед выполнением команды необходимо убедиться, что используется правильная резервная копия.

Для восстановления изображений и их метаданных необходимы резервная копия PostgreSQL (`images_db.dump`) и резервная копия файлов изображений (`backups/images/`).

Для сохранения данных пользователей необходимо также создать резервную копию `users.json`.
